# UI Mockup: Design and Plan (Plan 3a)

> **For agentic workers:** this is a short, design-level plan for a throwaway-friendly UI mockup. Implement task by task, commit after each, follow the conventions below.

**Goal:** A clickable Android app (`:app`) showing all five screens from spec §8, driven by fake data. It installs and runs on an API 36 emulator on this PC.

**Scope:** UI only. No networking and no `:proxy-core` dependency yet. Everything the UI needs goes through a `SessionRepository` interface. This plan ships `FakeSessionRepository`; Plan 2's real service will implement the same interface.

**Tech:** Kotlin, Jetpack Compose (Material 3, dynamic color on API 31+), Navigation Compose, `com.google.zxing:core` for QR bitmaps. `minSdk 29`, `compileSdk`/`targetSdk 36` (the spec's 37 waits for the real app). Debug build only.

## SessionRepository (the seam Plan 2 replaces)

```kotlin
enum class SessionPhase { IDLE, STARTING, RUNNING, DEGRADED, STOPPING }
enum class ClientPlatform { ANDROID, IPHONE }
data class SlotUi(val id: String, val name: String, val platform: ClientPlatform, val ip: String?, val bytesUp: Long, val bytesDown: Long, val activeTunnels: Int)
data class SessionUi(val phase: SessionPhase, val degradedReason: String?, val cellularUp: Boolean, val ssid: String, val proxyHost: String, val port: Int, val slots: List<SlotUi>, val maxClients: Int)
data class HostSettings(val ssidSuffix: String, val password: String, val maxClients: Int, val port: Int, val prefer5Ghz: Boolean)
data class DeviceInvite(val slotId: String, val wifiQr: String, val pacUrl: String, val mobileConfigUrl: String)
enum class CheckStatus { OK, ACTION_NEEDED, NOT_APPLICABLE }
data class SetupCheck(val title: String, val detail: String, val status: CheckStatus)
data class LogEntry(val timeMs: Long, val message: String)

interface SessionRepository {
    val session: StateFlow<SessionUi>
    val settings: StateFlow<HostSettings>
    val checks: StateFlow<List<SetupCheck>>
    val log: StateFlow<List<LogEntry>>
    fun start()
    fun stop()
    fun addDevice(name: String, platform: ClientPlatform): DeviceInvite?   // null when slots are full
    fun inviteFor(slotId: String): DeviceInvite?
    fun revoke(slotId: String)
    fun updateSettings(settings: HostSettings): Boolean                    // false if maxClients < active slots
}
```

**Fake behaviour:** the fake is constructed with a `CoroutineScope` and an injectable clock/delay so it can be tested.
- `start()` goes IDLE → STARTING (1.5 s) → RUNNING.
- While RUNNING, each active slot's counters grow every second. About 30 s after start it goes DEGRADED ("No mobile data") for 4 s, then back to RUNNING.
- `stop()` goes STOPPING (0.5 s) → IDLE.
- Initial seed data: two slots ("Ben's iPhone" on iPhone, "Pixel 7" on Android), settings `DIRECT-wp-HostPhone` / `correct horse battery` / maxClients 3 / port 8080, two checks needing action ("Battery optimisation", "Samsung: Never sleeping apps") and the rest OK.
- Every phase change and revoke is appended to the log.
- Tokens are 22 base64url characters from `SecureRandom`.
- `pacUrl = "http://192.168.49.1:8080/<token>.pac"`, `mobileConfigUrl` is the same with `.mobileconfig`.
- `wifiQr = "WIFI:T:WPA;S:<ssid>;P:<pass>;;"`, escaping `\ ; , : "` with a backslash.

## Screens (spec §8)

1. **Home:**
   - large phase-coloured status card;
   - a big Start/Stop button;
   - a mobile-data chip;
   - "Devices n/max";
   - a slot list with live ↑/↓ counters (human-readable bytes) and a Revoke button that asks for confirmation;
   - a footer line: "Web and most apps work. Calls, games and some apps won't."
2. **Devices / Add device:**
   - the slot list, plus an "Add device" button that opens a dialog (name, iPhone/Android segmented control);
   - when slots are full, the button is disabled with an explanation;
   - after adding, or tapping a slot, an invite sheet shows:
     - QR 1, the Wi-Fi network, blurred and hidden until "Tap to reveal";
     - QR 2, the auto-config URL, or the mobileconfig URL for iPhone;
     - the URL as copyable text;
     - 3–4 numbered steps for the platform (iPhone: "Open in Safari", install the profile in Settings, turn off mobile data; Android: Wi-Fi → Edit → Proxy → Auto-config, Private DNS Off/Automatic, turn off mobile data).
3. **Settings:**
   - network name, with a read-only `DIRECT-xy-` prefix and an editable suffix;
   - password with show/hide and a strength meter;
   - a max-clients slider (1–3). Lowering it below the active slots shows a message naming the slots to revoke first, and the save is rejected;
   - port and a "Prefer 5 GHz" switch;
   - a Save button, plus a warning that changing the password drops every device.
4. **Setup check:** cards with status icons. Each "action needed" card has a button that shows a Snackbar ("Would open system settings").
5. **Diagnostics:** a newest-first log in a monospace list, and an Export button that opens the Android share sheet with the log as text.
